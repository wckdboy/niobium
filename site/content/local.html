Choose DSH on your device and keep using the standard Niobium app. The same Home, Pixels, workshop and native chats connect to your local engine.

one app, two engines

Choose “Run Pixels locally” on the welcome screen, or select On device in Engines. DSH starts behind Niobium. Enter a model API key in the native provider settings, then create and chat with your Pixels as usual. The workshop creates real DSH agent presets from the persona and access you review.

Switch to Hermes whenever you want. Your saved Hermes connection remains available, and the local engine can stay running alongside it. Each engine keeps its own roster and conversation history; switching does not move chats between engines.

quietly local

iOS uses iSH-ARM64; ARM64 Android uses an APK-packaged PRoot engine. Both include pinned Alpine, Node and DSH. The Linux runtime is local; model requests use your configured provider. Android needs about 450 MB for its installed image.

Provider keys stay in DSH app storage. Local Pixels share a Linux workspace. Their reviewed presets select available tools; workspace scopes are operating instructions, not separate operating-system sandboxes. Hermes supplies group rooms and scheduled jobs.

advanced when you need it

The terminal, stock DSH web workspace, remote DSH connection and Stop controls live under Advanced controls in Engines. Changing a screen does not stop local tasks. Android keeps a foreground notification with Stop; iOS may suspend local execution while Niobium is backgrounded.

beta coverage

Five Android app-domain tests cover native Pixel preset creation, a prompt through real DSH to a controlled model server, streamed native replies and restored history, private authenticated HTTP/WebSocket access, native navigation, advanced WebView layout, Stop/restart and workspace preservation. The full iOS build 8 simulator acceptance app passed a controlled SSE model turn through real DSH, an eight-second Home-screen round trip, and restored history after a full app/guest restart. A unique reply marker prevents earlier history from satisfying the test. A physical iPhone 18 Pro Max on iOS 27.0.1 passed the build 7 native startup, Engines, Home-screen return and chat-UI smoke test.

Build 8 iPhone acceptance, broader physical-device checks, real-account provider turns, actual delegation, Android 16 KB pages, battery behavior and host bridges still need acceptance. Keys are not yet held in a separate native provider vault.
