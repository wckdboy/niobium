Choose local DSH and keep using the standard Niobium app. Your Pixels, workshop and native chats connect to the local engine.

one app, independent engines

On Android, choose “Run Pixels locally” on the welcome screen or select On device in Engines. On desktop, open Engines and start Local DSH. DSH starts behind Niobium. Enter a model API key in the native provider settings, then create and chat with your Pixels as usual. The workshop creates real DSH agent presets from the persona and access you review.

Switch to Hermes whenever you want. Your saved Hermes connection remains available, and the local engine can stay running alongside it. Each engine keeps its own roster and conversation history; switching does not move chats between engines.

quietly local

iOS uses iSH-ARM64; ARM64 Android uses an APK-packaged PRoot engine. Android includes pinned Alpine, Node and DSH. Desktop runs DSH directly as a host process using bundled Node, with no Linux emulator. The agent runtime is local; model requests use your configured provider. Android needs about 450 MB for its installed image.

Provider keys stay in DSH storage. Desktop uses an owner-only local credential file. Local Pixels share an engine workspace. Their reviewed presets select available tools; workspace scopes are operating instructions, not separate operating-system sandboxes. Local rooms run on the device; scheduled jobs still require Hermes.

advanced when you need it

The terminal, stock DSH web workspace, remote DSH connection and Stop controls live under Advanced controls in Engines. Changing a screen does not stop local tasks. Android keeps a foreground notification with Stop; iOS may suspend local execution while Niobium is backgrounded.

beta coverage

Android runtime checks cover real Pixel creation, a controlled DSH model stream, restored history, private access, native navigation, Stop/restart and workspace preservation. On iPhone, production build 14 passed four native startup, chat-attachment and background-return runs. A separate Debug acceptance app also passed a controlled model turn and history restoration after a cold launch.

Real-account turns, delegation, physical Android/16 KB devices, broader battery behavior and host bridges still need acceptance. Provider keys currently stay in DSH app storage.

native conversations

Hermes and local DSH retain separate connections, sessions and approvals. Selecting one keeps the other connected. Local Pixels use attributed DMs and rooms with bounded replies; rooms belong to the selected engine.

Reviewed messaging access exposes the actual Pixel directory and message tool. Unknown delivery receipts stay visible and are never replayed. iOS may pause local work in the background.

on your computer

Linux and macOS use a private DSH home and workspace. The stock DSH listener binds to a private Unix socket; Niobium exposes only its authenticated native API on loopback. Start and Stop are explicit, and quitting the app stops its local engine. Hermes continues on its host. The native View menu offers 100%, 125% and 150% text. Engine setup stacks when it needs more room.

Local tools have your account’s permissions. Reviewed access is an agent policy, not an OS sandbox. Desktop gateway and image keys use session-only storage by default, with optional macOS Keychain or Linux Secret Service storage for named accounts. Saved keys load only when you choose Use. The vaults protect data at rest at the OS-user level; local processes and agent tools with that account can access saved values. DSH provider keys keep their owner-only file. Native desktop setup supports DeepSeek, OpenAI, Anthropic and a compatible endpoint with explicit model limits. Choose a default for new chats; existing conversations keep their model. Open model pickers refresh after setup. Android’s key-saving screen activates the supported vendor routes. Configured status confirms local setup; it does not validate a provider account.

android chat quality

Photos use the system picker and bounded background preparation, with orientation correction, transparency and a small preview. Read older DM or room messages without streaming pulling you away. Latest messages returns to the conversation’s end.

Drafts clear after engine acceptance. Opaque pending receipts survive app restart and hold uncertain sends for review. Known abandoned photo uploads are detached by their exact handle. Check the conversation and any queued photos after a lost connection; prompts never replay automatically. Text drafts remain in memory and do not survive process death.
