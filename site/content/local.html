Choose DSH on your device and keep using the standard Niobium app. The same Home, Pixels, workshop and native chats connect to your local engine.

one app, independent engines

Choose “Run Pixels locally” on the welcome screen, or select On device in Engines. DSH starts behind Niobium. Enter a model API key in the native provider settings, then create and chat with your Pixels as usual. The workshop creates real DSH agent presets from the persona and access you review.

Switch to Hermes whenever you want. Your saved Hermes connection remains available, and the local engine can stay running alongside it. Each engine keeps its own roster and conversation history; switching does not move chats between engines.

quietly local

iOS uses iSH-ARM64; ARM64 Android uses an APK-packaged PRoot engine. Both include pinned Alpine, Node and DSH. The Linux runtime is local; model requests use your configured provider. Android needs about 450 MB for its installed image.

Provider keys stay in DSH app storage. Local Pixels share a Linux workspace. Their reviewed presets select available tools; workspace scopes are operating instructions, not separate operating-system sandboxes. Local rooms run on the device; scheduled jobs still require Hermes.

advanced when you need it

The terminal, stock DSH web workspace, remote DSH connection and Stop controls live under Advanced controls in Engines. Changing a screen does not stop local tasks. Android keeps a foreground notification with Stop; iOS may suspend local execution while Niobium is backgrounded.

beta coverage

Android runtime checks cover real Pixel creation, a controlled DSH model stream, restored history, private access, native navigation, Stop/restart and workspace preservation. On iPhone, production build 14 passed four native startup, chat-attachment and background-return runs. A separate Debug acceptance app also passed a controlled model turn and history restoration after a cold launch.

Real-account turns, delegation, physical Android/16 KB devices, broader battery behavior and host bridges still need acceptance. Provider keys currently stay in DSH app storage.

native conversations

Hermes and local DSH retain separate connections, sessions and approvals. Selecting one keeps the other connected. Local Pixels use attributed DMs and rooms with bounded replies; rooms belong to the selected engine.

Reviewed messaging access exposes the actual Pixel directory and message tool. Unknown delivery receipts stay visible and are never replayed. iOS may pause local work in the background.
