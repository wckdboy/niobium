Kotlin and Compose on Linux, macOS and Android. Shared transport, Pixel models and art reduction; a desktop workspace and a mobile interface, with the agent engine you choose. The existing SwiftUI client is retained while iOS release work is parked.

the connection

Niobium uses Hermes’ WebSocket gateway or a native adapter for local DSH. The same native app works with either provider. Android tokens use Keystore. Desktop gateway tokens use session-only storage by default. Named accounts can opt into macOS Keychain or Linux Secret Service and load only when you choose Use. Remote gateways require HTTPS; HTTP is reserved for literal loopback addresses used by local runtimes. Authenticated probes and WebSocket handshakes do not follow redirects. The app discovers runtime capabilities and reports unavailable operations instead of inventing a successful result.

Model changes and Stop controls use the gateway’s current session revision and execution generation. Resumed chats recover their running state and pending approvals.

bot mode

A Pixel is a Hermes profile or a local DSH agent preset. Opening it returns to its native chat and persistent session. @mentions identify teammates; Hermes handles attributed inter-agent messages. Group rooms run on a capable gateway and can continue after the phone disconnects.

Each Pixel’s appearance and companion are stored with its profile metadata. The clients share exact 48×48 portraits, nearest-neighbour display and independent 16×16 companions. Pixel studio offers nine visual traits, pinned remixes and restoration of the authored cast.

companions

The parent Pixel decides when a task benefits from delegation. Android shows the real child task, goal, status, tool count and available transcript. A correction is labelled queued until the backend delivers it. Failed delegations stay visible.

scope

Hermes has a larger feature surface than Niobium currently exposes. Sessions, tools, skills, MCP inventory, routines, rooms, photos and dictation are implemented to varying depth. Connector account flows, memory editing, project management, complete attachment support and background delivery still need work. See the method audit for the current detail.

desktop scope

The desktop preview provides independent Hermes/local DSH connections, persistent chats, streamed tools, approvals and questions, model selection, rooms and reviewed Pixel creation. Its wardrobe and optional AI atelier use the same portable character format as Android. Keyboard controls expose focus and selection. Text size and setup layouts adapt; chats preserve your place while you read older messages. Latest messages resumes following a stream. Native provider setup activates DeepSeek, OpenAI, Anthropic and compatible endpoints through DSH’s settings API. Revision checks protect concurrent edits, and advanced custom model settings stay in the advanced controls.

Desktop photos/dictation, broad skill/MCP/routine controls, full companion task monitoring and the DSH vault bridge remain follow-up work. Full Hermes parity remains the target.

android delivery

Before a direct send, Android persists an opaque account/session receipt. Rapid taps cannot submit the same in-flight send twice. A missing acknowledgement locks sending until explicit review, without automatic prompt replay. Picker, dictation and upload callbacks stay with their engine and conversation. Photos are resized to a 2048-pixel edge and encoded within 4 MiB; raw input is capped at 16 MiB.

Photos use the engine’s upload and detach contracts. After connection loss, inspect queued photos as well as the conversation before allowing another send. Full server outbox/replay reconciliation remains follow-up work.
