what changed

Choose session-only use or save named Hermes and image accounts in macOS Keychain or Linux Secret Service. Saved gateways bind their exact URL and name. Use loads the selected credential; confirmed deletion clears its linked active session and removes the vault copy. Locked, unavailable, denied and unconfirmed outcomes stay visible.

Disconnect, Clear session and app shutdown invalidate pending loads. Image receipts retain credential scope. Rotated keys and older receipts require explicit account confirmation and a successful status response; interrupted generation requests are never replayed automatically.

the storage boundary

Vault storage protects values at rest at the OS-user level. Same-user processes and local agent tools can access saved values. The unsigned helper does not validate a signed parent, and Linux Secret Service shares the user session. Session-only use is the default. DSH provider keys keep their owner-only file; its vault bridge remains separate work.

verified

42 desktop, 33 shared-core, seven additional Android JVM, 85 Node and 15 Python checks. Native macOS acceptance uses an isolated temporary keychain and verifies the user’s search list is unchanged. Native Linux acceptance always creates an owned private D-Bus/keyring service, rejects CLI bypasses and restores credentials after a service restart.

Both suites exercise account/kind isolation, locked reads/writes/deletes and idempotent deletion. Native Linux/macOS installer checks exercise actual packaged launchers, private DSH, helper integrity and executable modes. No real provider account or billable model request is used.
